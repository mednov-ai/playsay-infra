# Production hotfix 01.006.14: user deletion checkpoints

## Scope and authorization

The owner explicitly authorized production delivery on 2026-09-06 after confirming that Maria, who has both TEACHER and ADMIN roles, still received `USER_DELETE_REPLACEMENT_REQUIRED` while deleting users. The production behavior contract is that ADMIN privileges prevail over the teacher role: an ADMIN and an ADMIN+TEACHER can delete admins, teachers, and students with the same rights as any other admin; only the last admin is protected. Student deletion detaches the student from teachers and proceeds without replacement when the caller is an admin.

Platform source `751b8b7b977a7d57325d46b80db3562723f5818b` is the isolated hotfix source on top of production/develop `61a1bfdb945da03a06ed474e6eda7c1f25e66c47`. It contains only the user-deletion checkpoint and feedback patch set:

- backend checkpointed user-deletion stages and legacy failed-operation classification;
- admin deletion semantics that do not let the teacher role reduce admin privileges;
- app-wide localized error toast handling for ru/en/de/fr;
- focused regression coverage and synchronized product/OpenSpec documentation.
