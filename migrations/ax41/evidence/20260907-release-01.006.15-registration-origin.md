# Production hotfix 01.006.15: registration email origin

## Scope

The owner authorized a production hotfix after platform delivery inspection confirmed that a recent registration-confirmation email contained the direct `.school` URL. No recipient address, confirmation token, message content or provider credentials are retained in this evidence.

The only runtime configuration difference from release/01.006.14 is `registrationService.publicBaseUrl=https://online.honeyschool.ru` in the registration-service production values. Confirmation and password-reset email links share that setting. Dev keeps its dev origin. Previously sent messages and email-log replay preserve their original URLs.

- Platform/accepted source: `751b8b7b977a7d57325d46b80db3562723f5818b`, identical to the running release/01.006.14 source; no product image rebuild was needed.
- Infra fix on develop: `98cec39`; the release branch was seeded from the actual production infra branch with only this reviewed fix, avoiding the unrelated, undeployed release/01.007.00 desired state.

- Every production chart's image/build metadata is unchanged. The full Helm-directory diff against release/01.006.14 contains only the publicBaseUrl line. All production ArgoCD application revisions consistently target release/01.006.15.

Helm lint/render and diff whitespace checks passed. The existing disposable dev smoke passed registration start, inbox receipt, confirmation/repeated confirmation, first password sign-in with STUDENT role, profile verification, reset email/password change, old-password rejection, new-password sign-in and identity/mailbox cleanup. Its sign-in step uses the existing token-endpoint password-grant smoke implementation; this evidence does not claim separate interactive OIDC browser acceptance.

No Keycloak change or database restore is part of this hotfix.

## Rollout

The operator changed the root revision through the authenticated ArgoCD API and synced the exact ready candidate, then synced registration-service. No direct workload apply, secret edit, image rebuild or manual database migration was used.

## Production acceptance

All 19 ArgoCD applications are Synced/Healthy on release/01.006.15. Only the registration-service pod UID changed; other application pods remained intact. Both online origins returned HTTP 200 and API UP. The running registration-service base URL is `https://online.honeyschool.ru`.

Two disposable production journeys passed, starting independently on `.ru` and `.school`. Each received a real confirmation email whose URL origin was explicitly asserted to equal `https://online.honeyschool.ru`, followed it successfully, verified repeated confirmation, signed in, read the student profile, received a real reset email with the same asserted `.ru` origin, changed the password, rejected the old password, signed in with the new password and cleaned up the synthetic identity and mailbox. No real student email was resent. The smoke uses Chromium for registration/confirmation and the retained token-endpoint sign-in checks described above.

After successful acceptance, the production current-release pointer on infra develop advances from release/01.006.14 to release/01.006.15. The ready release candidate stays immutable; bookkeeping does not rebuild or redeploy it. The unrelated release/01.007.00 remains unpromoted.

## Rollback

Return the production root to release/01.006.14 and sync registration-service through ArgoCD. This restores the old email origin with identical application images; no database restore is required. Already issued emails remain unchanged by either direction of the rollout.
